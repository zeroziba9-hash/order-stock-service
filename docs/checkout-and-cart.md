# 가격 확인 주문과 계정 장바구니

상품을 담은 시점과 주문 시점의 가격이 달라질 수 있습니다. 웹 화면은 최신 이름·단가·수량·합계를 먼저 보여주고 사용자가 확인한 조건으로 주문합니다.
장바구니는 계정별 MySQL에 저장하며 다른 기기에서 다시 로그인해도 이어서 조회합니다. 담는 것만으로 재고를 예약하지 않습니다.

## 가격 확인과 확정

1. `POST /orders/cart/quote`에 중복 없는 1~20종의 `items: [{productId, quantity}]`를 보냅니다.
2. 현재 상품명·가격·수량·재고·판매 상태와 정확한 합계 문자열 `totalAmount`, 10분 유효한 `expiresAt`을 반환합니다.
3. 판매 중지·재고 부족 항목이 있으면 `canOrder=false`, `quoteId=null`이며 화면에 해당 상품을 표시합니다.
4. 주문 가능하면 확인 화면의 최신 금액에 동의한 뒤 `POST /orders/cart/checkout`에 `{quoteId}`와 필수 `Idempotency-Key`를 보냅니다.
5. 서버는 본인 확인 정보·기한을 확인하고 상품을 ID 오름차순으로 잠급니다. 단가·상품 정보 버전·판매 상태·수량을 다시 검사합니다.
6. 상품 잠금을 기다리는 사이 기한이 지난 경우도 거부합니다. 주문·항목·재고·원장·키 완료 연결·확인 정보 소비를 한 트랜잭션에 저장합니다.

가격이나 상품 정보 버전이 달라지면 `409 QUOTE_CHANGED`, 기한이 지났으면 `409 QUOTE_EXPIRED`로 주문을 만들지 않습니다.
재고만 달라진 경우 필요한 수량이 남아 있으면 주문할 수 있습니다. 이름·가격·판매 상태를 바꿨다가 되돌려도 수정 버전이 다르면 재확인이 필요합니다.
단가×수량과 합계는 서버에서 정수 오버플로를 검사합니다. 합계는 브라우저 정수 정밀도를 잃지 않도록 십진 문자열로 보내고 BigInt로 표시합니다.

동일 계정·키·quoteId의 완료 요청은 기한 경과·상품 변경·확인 정보 정리 이후에도 기존 주문을 반환합니다.
다른 키로 이미 소비한 확인 정보를 제출하면 `409 QUOTE_ALREADY_USED`이며 두 번째 주문을 만들지 않습니다.
다른 확인 정보에 같은 키를 쓰면 `409 IDEMPOTENCY_KEY_REUSED`입니다. 다른 회원의 확인 정보는 조회할 수 없습니다.
계정당 유효한 확인 정보는 최대 100개이며, 만료 후 하루 지난 정보는 시간당 최대 1,000개씩 정리합니다. 완료 요청 연결은 별도로 보존합니다.

기존 `/orders`·`/orders/cart`는 현재 서버 가격으로 주문하는 호환 API입니다. 이 API 자체는 가격 확인을 강제하지 않습니다.
웹의 단일 상품 주문과 장바구니 주문은 모두 확인 API를 사용합니다. 과거에 생성된 주문·항목·키·재고를 바꾸지 않습니다.

## 장바구니 저장과 동시 수정

`GET /cart`는 `{revision, items}`를 반환합니다. 각 항목에는 현재 이름·가격·재고·판매 상태와 담은 수량이 포함됩니다.
`PUT /cart`에는 직전 `revision`과 전체 `items: [{productId, quantity}]`를 보냅니다. 빈 배열은 장바구니를 비웁니다.
계정별 헤더를 잠그고 버전을 비교하므로, 최초 두 기기의 동시 저장도 한 요청만 성공합니다.
오래된 버전은 `409 CART_CHANGED`이며 화면은 최신 장바구니를 다시 불러옵니다. 자동으로 덮어쓰지 않습니다.
주문 성공 후 장바구니 비우기도 같은 버전을 검사하므로 다른 기기의 추가·수량 변경을 보존합니다.
주문과 장바구니 비우기는 별도 요청입니다. 비우기에 실패해도 완료 주문은 취소되지 않으며 화면에 장바구니 재확인을 안내합니다.

기존 탭 저장 장바구니는 서버 장바구니가 버전 0의 빈 상태일 때 한 번 가져옵니다. 이미 저장된 다른 기기의 장바구니가 있으면 서버 내용을 사용합니다.
불확실한 주문의 키·확인 ID·당시 장바구니 버전은 계속 탭의 sessionStorage에 먼저 저장합니다.
새로고침 후에도 동일 요청으로 결과를 확인하며, 이전 V17 장바구니 보류 요청은 원래 `/orders/cart` 본문·키로 재시도합니다.
탭 종료·저장소 삭제 뒤에는 보류 키를 복구할 수 없습니다. 장바구니 데이터는 서버에 남지만 새 주문 전에 내 주문을 확인해야 합니다.

## 스키마와 검증

V18은 `saved_carts`, `saved_cart_items`, `checkout_quotes`, `checkout_quote_items`를 추가합니다. 기존 업무 표의 데이터는 수정하지 않습니다.
확인 주문의 요청 해시는 quoteId에서 계산합니다. 기존 요청 표의 상품·수량 열은 호환 목적으로 양의 자리표시자를 저장하며 확인 주문 항목의 근거로 사용하지 않습니다.

MySQL 통합 테스트에서 변경 후 전체 롤백·만료·소유권·응답 재시도·서로 다른 키의 동시 소비·원장 실패 후 재사용·장바구니 동시 저장을 검사합니다.
데스크톱·모바일에서 가격 변경 표시·확인 중 변경 거부·다른 접속 장바구니·충돌 복구·이전 요청 재시도를 검사합니다.
실제 API 계약은 [REST Docs 가이드](api-documentation.md), 장애 검증은 [복구 검증](recovery-verification.md)을 따릅니다.
