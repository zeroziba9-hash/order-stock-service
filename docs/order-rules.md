# 주문 규칙

- 주문 수량은 1개 이상이다.
- 존재하는 상품만 주문할 수 있다.
- 상품 가격은 서버가 조회하며, 주문 시점의 가격을 주문 항목에 보존한다.
- 재고보다 많은 수량을 판매할 수 없다.
- 주문 저장과 재고 차감은 하나의 트랜잭션으로 처리한다.
- 주문 저장에 실패하면 재고 차감도 롤백한다.
- 동시 요청이 들어와도 재고가 음수가 되거나 재고보다 많이 판매되지 않는다.
- 취소 시 재고는 한 번만 복구한다.
- 반복 취소는 최초 취소 결과와 시각을 그대로 반환한다.
- 취소 상태 저장과 재고 복구도 하나의 트랜잭션으로 처리한다.
- 생성 요청의 키와 내용이 같으면 기존 주문을 반환하고 추가 재고 차감을 하지 않는다.
- 같은 키로 다른 상품·수량을 요청하면 거부한다.
- 생성 실패 시 요청 키도 롤백하여 같은 키로 다시 시도할 수 있다.

단일 상품 API와 장바구니의 최대 20종 상품 주문 생성·조회·취소, 모의 결제·전액 환불을 구현했습니다.
여러 상품은 중복 없이 ID 순서로 잠그며 한 상품이라도 실패하면 모든 항목·재고·원장·요청 키를 롤백합니다.
트랜잭션 전체에서 상품 행의 쓰기 잠금을 유지하며, DB 통합 테스트로 재고 부족·롤백·동시 주문을 검증합니다.
주문 생성은 결제 완료를 의미하지 않으며 상태는 `CREATED`입니다.
취소는 주문 행을 먼저 잠근 뒤 상품 ID 순서로 상품 행을 잠그고 재고를 복구합니다.
미결제 취소된 주문과 항목은 삭제하지 않으며, 상태는 `CANCELLED`, 취소 시각은 UTC로 보관합니다.
단일 상품 API는 키를 생략하면 각각 새 주문을 생성합니다. 장바구니 주문은 요청 키가 필수입니다.
키는 사용자별 범위에서 대소문자를 구분하며 만료 없이 보관합니다.
주문의 소유자는 로그인한 회원 정보로 결정하며, 본인 주문만 조회·취소할 수 있습니다.
기존 익명 주문과 키는 소유자 NULL로 보존하고 회원에게 임의로 귀속하지 않습니다.

## 결제 규칙

- 결제 금액은 주문 당시 총액을 사용한다. 현재 상품 가격이나 요청 본문의 금액을 사용하지 않는다.
- 결제 성공 시 `CREATED → PAID`, 실패 시 `CREATED`를 유지하며 실패 이력을 보존한다.
- 재고는 주문 생성 때 예약한다. 결제 성공·실패 시 재고를 추가로 변경하지 않는다.
- 미결제 주문은 기본 30분 뒤 결제할 수 없으며 자동 작업이 `EXPIRED`로 전환하고 재고를 한 번 복구한다.
- 결제 기한과 같거나 늦은 새 결제는 작업 실행 전에도 `ORDER_EXPIRED`로 거부한다.
- 결제와 취소는 동일한 주문 행 잠금을 사용한다. 취소가 먼저면 결제를 거부하고, 결제가 먼저면 취소를 거부한다.
- 성공 결제는 주문당 최대 한 건이다. 애플리케이션 잠금과 DB 유니크 제약으로 보장한다.
- 결제 키는 주문별로 구분한다. 같은 키·같은 결과 선택은 원래 결제 이력을 반환한다.
- 실패 결과를 성공으로 바꿔 재시도할 때는 새 키를 사용한다.
- 결제 저장과 주문 상태는 하나의 트랜잭션으로 처리한다. DB 오류 시 모두 롤백한다.
- 결제 완료 주문의 취소는 환불 API에서 처리한다. `/cancel`은 결제 완료 주문에 `REFUND_REQUIRED`를 반환한다.

모의 결제는 외부 결제사 호출이 없는 로컬 시뮬레이션이다. 실제 결제 연동에는 별도 상태와 복구 절차가 필요하다.
마감·배치·재시도·기존 주문의 변경은 [자동 만료 안내](order-expiration.md)를 참고한다.

## 환불 규칙

- `PAID` 주문의 성공 결제를 전액 환불한다. 부분 환불은 지원하지 않는다.
- 환불 금액과 결제 ID는 서버가 저장된 성공 결제에서 결정한다.
- 환불 성공 시 `PAID → REFUNDED`로 전이하고 재고를 한 번만 복구한다.
- `paidAt`과 성공 결제 이력은 유지한다. `refundedAt`과 `cancelledAt`에는 최초 환불 성공 시각을 기록한다.
- 환불 실패는 이력을 커밋하되 주문은 `PAID`이고 재고도 유지한다.
- 환불 키는 주문별로 구분한다. 같은 키·같은 결과 선택은 최초 이력을 반환하고 결과 변경은 거부한다.
- 환불 저장·주문 취소·재고 복구는 하나의 트랜잭션이다. DB 저장 오류 시 모두 롤백한다.
- 환불·결제·취소는 동일한 주문 잠금을 공유하고 재고 복구는 상품 ID 순서로 잠근다.
- 환불 완료 주문의 `/cancel`은 현재 `REFUNDED` 상태를 반환하며 재고를 추가로 늘리지 않는다.
- 환불 완료 후 새 결제·환불은 거부한다. 과거 결제·환불 키의 재시도는 원래 이력만 반환한다.
