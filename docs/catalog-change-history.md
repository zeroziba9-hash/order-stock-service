# 상품 정보 변경 이력

관리자 `/catalog.html`에서 선택 상품의 이름·가격·판매 상태 변경을 확인합니다.
변경한 관리자 ID, UTC 시각, 변경 전후 값과 수정 버전을 저장합니다. 이메일·비밀번호는 반환하지 않습니다.

## 저장 규칙

상품 행 잠금과 revision 확인 후 상품 수정·이력을 같은 트랜잭션에 저장합니다.
상품 SQL을 flush한 뒤 이력 INSERT가 실패해도 둘 다 롤백합니다. 바깥 트랜잭션 롤백도 동일합니다.
두 관리자가 같은 버전으로 수정하면 한 건만 반영되고 다른 요청은 `409 CATALOG_CHANGED`입니다.
`(product_id, after_revision)` 유니크 제약과 전후 버전 차이 1 CHECK 제약을 적용합니다.

상품명 양끝 공백 제거 후 이름·가격·판매 상태가 모두 같으면 수정 버전과 이력을 늘리지 않습니다.
같은 내용이어도 오래된 revision은 409입니다. 응답을 받지 못했으면 목록과 이력을 조회해 현재 상태를 확인하세요.
상품 등록·재고 변경은 이 표에 기록하지 않습니다. 재고는 [전체 원장](catalog-and-ledger.md)을 사용합니다.

V12는 새 이력 표만 만듭니다. 기존 상품·주문·재고 값은 변경하지 않고 이전 수정을 소급 생성하지 않습니다.
V12 이후 앱의 상품 수정 경로에서 발생한 변경만 저장합니다. 웹 API에 이력 수정·삭제는 없습니다.
DB 운영자의 직접 SQL은 자동 기록되지 않고, DB 운영자의 기록 변조까지 막는 저장소는 아닙니다.

## 조회와 화면

`GET /admin/products/{id}/changes?beforeId=100`은 관리자 로그인과 현재 DB 관리자 역할이 필요합니다.
일반 회원·권한을 회수한 기존 세션은 조회할 수 없습니다. 상품 ID와 선택 커서는 양수여야 하며 없는 상품은 404입니다.
최신 ID순 최대 20건과 `nextBeforeId`를 반환합니다. 다음 페이지는 이 ID 미만이며 마지막은 null입니다.
페이지 사이에 새 수정이 추가돼도 이전 커서로 내려갈 때 같은 변경을 중복 표시하지 않습니다.

각 변경은 `changeId`, `productId`, `actorId`, `createdAt`, `before`, `after`입니다.
전후 객체는 `name`, `price`, `selling`, `revision`을 포함합니다.
실제 응답과 필드 계약은 [테스트 기반 API 가이드](api-documentation.md)에서 생성합니다.

화면은 바뀐 필드의 전후 값과 로컬 시각을 표시합니다. 상품명은 textContent로 안전하게 표시합니다.
상품 전환 시 이전 기록을 비우고 이전 요청의 늦은 응답을 무시합니다. 조회 실패는 이력 영역에 표시하며
이력 새로고침으로 복구합니다. 이전 변경 더 보기는 선택 상품의 다음 커서를 사용합니다.

## 검증

- 실제 MySQL에서 두 관리자·전후 스냅샷·UTC 시각·동시 수정·no-op·오래된 수정·입력 오류를 확인합니다.
- 실제 이력 SQL 이후 강제 오류와 바깥 트랜잭션 롤백에서 상품·이력이 함께 취소되는지 확인합니다.
- 상품별 커서·페이지 사이 새 수정·관리자 권한 회수·CSRF·실행자 위조를 검증합니다.
- 데스크톱·모바일에서 실제 수정·no-op·21건 커서·HTML 문자 안전 표시·가로 넘침·늦은 응답·통신 실패 복구를 검증합니다.
- V8 업그레이드 CI는 V12 적용과 빈 이력 표를 확인해 존재하지 않는 과거 수정을 만들지 않는지 검증합니다.

전체 관리자 활동·변경 사유 입력·기간별 검색·외부 불변 저장소는 별도 기능입니다.
