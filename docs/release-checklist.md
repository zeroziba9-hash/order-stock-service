# 릴리스 후보 확인

첫 후보 이름은 `v0.1.0-rc.1`로 제안합니다. 이 문서는 태그·GitHub Release를 생성하거나 공개 배포한 기록이 아닙니다.
브랜치 변경을 검토·병합한 뒤 실제 검증한 **main 커밋**으로 후보를 고정합니다.

## 1. 코드와 이미지 고정

1. PR의 변경 파일과 CI를 확인합니다. 새 브랜치의 검사 결과를 이전 커밋의 통과 기록으로 대체하지 않습니다.
2. 작업 트리가 깨끗한지 확인하고 커밋 SHA와 이미지 ID를 기록합니다.
3. 동일 SHA에서 빌드한 이미지를 시험·배포하고 변경 기록을 확정합니다.
4. API 문서·런처·사용 흐름과 실제 동작이 맞는지 확인합니다.

```bash
git status --short
git rev-parse HEAD
docker build --label org.opencontainers.image.revision=$(git rev-parse HEAD) -t stockroom:0.1.0-rc.1 .
docker image inspect stockroom:0.1.0-rc.1 --format '{{.Id}}'
python3 scripts/release-manifest.py --version v0.1.0-rc.1 --image stockroom:0.1.0-rc.1 --output build/release/manifest.json
```

로컬 후보 기록 도구는 미커밋 변경과 HEAD가 다른 이미지 revision 라벨을 거부합니다.
기록에는 식별 정보만 넣으며 테스트 통과나 배포 완료를 라벨로 추정하지 않습니다.
위 빌드 예는 Linux shell 기준입니다. 이미지를 배포 후 다른 코드로 같은 태그에 덮어쓰지 않습니다.
현재 런타임은 Java 17·MySQL 8.4이고 마지막 스키마는 V23입니다.
V23은 카드 테스트 결제의 상태·작업 임대·PG 멱등 키를 저장하는 `toss_payments`를 추가합니다.
키 미설정 시 기능은 비활성화하며 기존 주문·회원·상품을 변경하지 않습니다.

## 2. 로컬에서 확인할 항목

- 두 재고 차감 방식의 백엔드 CI·REST Docs와 Compose·HTTPS·백업·복구 CI 통과.
- Chromium·Firefox·WebKit의 주문·만료·인증 제한과 접근성 검사 통과.
- 가짜 SDK·HTTP PG의 카드 승인·전액 환불·응답 유실 복구와 복원 후 조회 전용 전환 확인.
- 실제 데모의 상품·회원·주문·원장 보존. 기능 검사는 별도의 일회용 DB에서 수행.
- Windows PowerShell 5.1에서 시작·상태·중지·재시작, 없는 볼륨의 시작 차단 확인.
- 320 CSS px 배치·텍스트 확대, 키보드 탐색과 팝업 복귀 확인.

자동 접근성 검사는 모든 접근성 요구 충족이나 스크린리더 실사용 검증을 뜻하지 않습니다.
Playwright WebKit은 실제 iPhone Safari와 다릅니다.

## 3. 공개 환경 준비 후 확인할 항목

현재 서버·도메인이 없으므로 다음 항목은 미완료로 유지합니다.

| 항목 | 실행·기록 |
|---|---|
| 서버·도메인·DNS | [운영 사전 검사](production-readiness.md), 실제 서버 OS·할당 자원·도메인 기록 |
| 외부 HTTPS | `verify-deployment.py`를 외부 네트워크에서 실행, 인증서·리다이렉트·권한·prod 모의 차단 확인 |
| 외부 메일 | [SMTP 설정](password-recovery.md), 실제 수신·링크·한 번만 변경·기존 세션 종료 확인 |
| 토스 테스트 결제 | [테스트 키 설정](toss-test-payments.md), 실제 결제창 인증·승인 조회·전액 취소 확인. 실제 과금·prod 활성화와 별개 |
| 서버 밖 복구 | [백업·복원](backup-restore.md), 원본과 분리한 새 DB에서 업무 데이터·이미지·원장·세션 무효화 확인 |
| 장치 확인 | 실제 iPhone Safari의 로그인·주문·복구·파일 선택과 화면 확대 확인 |
| 운영 관측 | 경고 수신 경로·대응 담당·백업 주기와 보관·실제 장애 복구 시간 기록 |

사전 검사·로컬 Mailpit·같은 PC의 빈 DB 복원 결과를 외부 검증 완료로 기록하지 않습니다.
시험 계정 정보·메일 링크·환경 파일·SQL·백업 원본을 공개 아티팩트에 넣지 않습니다.

## 4. 업그레이드·실패 대응

업그레이드 직전 백업과 체크섬을 만들고 별도 암호화 보관합니다.
V16에서 제거한 열이 있으므로 V16 이전 이미지를 현재 DB에 직접 연결하지 않습니다.
신규 이미지가 준비되지 않으면 트래픽을 열지 않고 호환 수정 버전으로 진행하거나,
백업을 별도의 새 DB에 복원하고 해당 스키마와 호환되는 이미지를 검증한 후 전환합니다.
볼륨·Flyway 이력을 삭제해 되돌리지 않습니다.

완료 기록에는 커밋·이미지 ID·UTC 시각·Flyway 버전·검사 보고서 경로·복구 결과와
아직 확인하지 않은 항목을 함께 남깁니다. 후보 공개와 운영 배포 완료를 구분합니다.
